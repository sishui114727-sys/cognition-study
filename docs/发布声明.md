## 一、这是什么

一个**可选插件**，给 QQ Agent / 大肥鱼 装一条"学习管线"：

```text
B站视频 → 取稿（字幕正文 + 元信息）→ 简报（时间轴要点）→ 手账（每天限量）
                                            ↘ 札记 / 检索（随时找回来）
```

不并入认知核心，不 import 核心代码，不共享数据目录。装它不需要先改核心的任何设置——两者互不干扰，也可以只装其中一个。

## 二、学习手账现在能做到什么

手账是这套东西的主体。它不是一个"记笔记的文本框"，而是一个**有账本、有额度、有校验、能修订、能导出**的小系统。

### 写

```text
study_journal_write    标题 + 正文（Markdown）
                       每天 2 篇、6000 字上限（两道闸，都可调）
                       同内容重复提交不会重复计数（幂等）
```

### 看

```text
study_journal_list     倒序列表，不带正文（不撑爆上下文）
                       可按某一天、或某个日期区间筛；支持分页
study_journal_get      读一篇：原条目 + 全部修订 + 引用稿件的标题与链接
study_journal_stats    总篇数、修订数、连续写作天数、本周、平均字数、
                       覆盖率分布（有正文 / 仅元信息）、失效引用数、今日额度
```

`study_journal_get` 返回的 `refs` 是 0.3.1 加的：

```json
"refs": [{ "id": "r:BV1UbyZB9ERb:1:217975bb",
           "title": "【TED演讲】必看100场TED演讲合集…",
           "url": "https://www.bilibili.com/video/BV1UbyZB9ERb",
           "coverage": "full", "fetchedAt": "…" }]
```

为什么加它：实测里她读到没有链接的手账后说了句「要翻原视频我把BV给你」，**BV 没给出来**——因为正文里只有 `readingIds`（`r:BVxxx:1:hash`），拿不到标题和 BV 号，想给链接还得再调一次工具。现在一次给全。

### 改

```text
study_journal_amend    追加一条修订，指向原手账 id
```

**手账能改，但不能编辑。** 直接覆盖会让"三个月后你不知道当时为什么那么想"。
所以修订是追加的：原条目一个字不动，新条目带 `revises` 指向它，列表和导出默认展示最新一版。
修订不占当天额度——它不是新的一天里的新想法，是改错字。

### 导

```text
study_journal_export   按天分组写成一份 Markdown（修订以引用块跟在原条目下）
                       落 data/exports/journal-<时间戳>.md，不覆盖旧文件
```

### 修

```text
study_journal_repair   校验 → 重建派生文件（索引 / 分卷）→ 再校验
                       账本永远不动；修好了什么，如实返回
```

### 三条不变量（每次读取都校验）

```text
1. 索引 total == 账本条数
2. 各卷记录数之和 == total
3. 每个 id 在所有分卷里恰好出现一次
```

索引和分卷都是**派生数据**，删了会自动重建；账本 `journal/ledger.jsonl` 是唯一真相。
读分卷必须带当前快照，快照过期会拒绝读——宁可多调一次工具，也不拿旧快照读半新半旧的分卷。

## 三、怎么用（三步）

```text
1. 装：解压社区包，plugin/ 放进 resources/app/plugins/cognition-study/
      config.json 的 trustedPlugins 里加 "cognition-study"，重启

2. 开：设置 → 学习管线 → 启用 + 填主人 QQ 号
      想让她读到字幕正文，再填 B站 SESSDATA（F12 → Cookies → SESSDATA）

3. 用：私聊发一条 B站 链接，说"学一下这个"
      她取稿 → 读简报 → 写一篇手账；当天第二篇要等额度
```

完整步骤见包内 [`INSTALL.md`](../INSTALL.md)，使用细节见 [`使用说明.zh-CN.md`](使用说明.zh-CN.md)。

## 四、让大肥鱼学习主人发来的 B站 视频

打开设置里的 **「主人发链接时自动提示学习」**（`learnOnLink`，默认关）后：

```text
主人私聊发来一条 B站 链接
        ↓
插件在消息尾部追加一行提示（只做本地判断，不下载、不改系统提示）
        ↓
提示里带：BV 号、这个视频是否已经取过稿（已取过就直接给稿件 id）
        ↓
大肥鱼据此调用 study_fetch → study_read → study_journal_write
```

为什么钩子里不直接下载：宿主给钩子 5 秒，取稿要打三四个请求，超时会被整轮跳过，还会卡住对话。
所以钩子只做"认链接 + 查本地"，真正的取稿交给工具，超时和失败都能被看见。

**边界（重要）**：

```text
只在「主人私聊」生效        群里别人贴的链接不触发
只在「有链接」时生效        平时零注入、零 token 成本
需要显式打开开关            默认关闭；装了不会静默改变任何一轮对话
不会假装读过正文            没配 SESSDATA 时提示里明说"只能读简介，别装读过"
```

## 五、和记忆核心（cognition-core）是什么关系

一句话：**两个独立插件，分工不同，不做同一件事。**

| | 记忆核心 cognition-core | 学习管线 cognition-study |
|---|---|---|
| 记什么 | 对话中的人和事、认知、原则 | 稿件（B站视频的正文）与手账 |
| 数据在哪 | `data/plugin-data/cognition-core/` | `data/plugin-data/cognition-study/` |
| 检索范围 | 它自己的记忆事件（+ **只读**手账 / 稿件 / 札记，0.24.0 起，默认关） | 它自己的稿件 / 手账 / 札记 |
| 上下文 | 按 token 预算注入记忆 | 只有主人私聊贴链接时才加一行提示 |
| B站 能力 | `bili.video` / `bili.search`：标题、UP、时长、简介 | 字幕正文 + 简报 + 手账 |

代码层面实测（0.24.0 / 0.3.1）：

```text
学习管线提到核心    0 处（代码里一次都没有）
核心提到学习管线    4 处，全是"数据目录路径"：src/host.js 的两行注释、一行路径拼接、
                    plugin.json 里 studyDataDir 的说明
互相 import         0 —— 没有共享模块，也没有跨插件的函数调用
```

换句话说：核心只知道"那边有个目录，我读一下"，不知道那边的代码长什么样。

### 核心侧的桥（0.24.0 起，只读）

```text
打开方式   核心设置 → 读取学习手账（studyBridgeEnabled，出厂 false）
能做什么   cognition_study_search 搜手账 / 稿件 / 札记，返回 id、日期、片段
           cognition_recall 记忆里没有可靠内容时，如实补一句"学习管家里有"
不做什么   不写手账、不改索引、不动账本；手账的唯一写入者仍然只有本插件
检索口径   中文二元组；标题 3 分 / 正文 1 分；近义词低一档
           原词覆盖率 ≥ 0.3；原词全没命中时要 ≥ 0.67（挡住混问噪声）
修订语义   原条目 + 修订折成一条线程，只取最新一版
缓存       按 (mtime, size) 失效——回忆是高频调用，不能每次重读几千行账本
```

### 可能的冲突（都是"用的人要注意"，不是崩溃）

```text
1. B站 能力有重叠
   核心的 bili.video 只给元信息（没有字幕），学习管线的 study_fetch 才给正文。
   都开着时，模型可能用核心那个"读一下"，结果只拿到标题。
   → 要说清：要正文就用 study_fetch。

2. 上下文开销叠加
   核心有记忆注入（按预算），学习管线有链接提示（一行）；
   桥打开后，回忆偶尔会多三行"学习管家里也有"。
   → 觉得贵就先关掉其中一边的开关，功能不受影响。

3. 内容可能被记两遍
   对话里聊了视频内容，核心会把它记成"人和事"；学习管线把手账记在它自己那边。
   两份内容不冲突，但会重复。
   → 建议：手账只写在 study，核心只记对话本身，别让模型把手账再"记一遍"。

4. 两边都能"搜"，但各自只搜自己的地盘
   桥只读不写，所以"在手账里引用核心的记忆"仍然只能靠对话。
```

## 六、对大肥鱼（她本人）的影响和作用

```text
变得更"读过"  以前她看 B站 只能拿到标题和简介，现在能拿到字幕正文，
              简报里有时间轴要点、高频词、数字与术语
记性有出处    手账每条都能追到稿件 id；修订保留历史，不会"改完就忘了原来怎么想"；
              0.3.1 起引用还带标题与链接，能直接把 BV 给出来
有节制        每天 2 篇 / 6000 字。不是拦她，是拦"一天八篇流水账"
不越权        所有工具 owner-only；只认主人私聊；SESSDATA 只发 bilibili.com
可自查        study_status / study_journal_stats / 只读面板，都能看到真实数字
不装也活着    插件默认关闭，关掉后核心照常工作，已写的手账还在，随时能读
```

对她最重要的变化不是"多了一个工具"，而是：**她说"我看过这个视频"时，背后真有一份读过的正文，和一条能翻回去的时间轴。**

### 真实对话里的两次实测（2026-10-31）

```text
第一次  问："上次那个讲意义的视频"
        她调 study_list → study_search → study_note_list → study_journal_get
        答对标题、四个支柱，并把修订里的"字幕没取全"一起说了
        但结尾说"要翻原视频我把BV给你"，BV 没给出来 → 这就是 0.3.1 修的东西

第二次  问："诶上次那个讲意义的视频是哪场来着"（更随口）
        0 次检索调用，直接凭上下文答："忘了我半小时前刚答过"
        另外自己补了英文原名 There's more to life than being happy
        ——这条不在我们的任何记录里，是她的背景知识（恰好对，但没有出处）

结论    顺手一问靠上下文就够；跨过上下文窗口才轮到手账与桥。
        所以桥的价值是兜底，不是主线——她更常直接调本插件的工具，这是对的。
```

## 八、已知边界（不藏）

```text
无 ASR            音频能匿名下载，但转写要几百 MB 模型，不该塞进插件
无自动摘要/提问    没有 LLM 就不装；要点只是指路，不是结论
字幕可能不完整    B站 端有时只返回一部分，甚至返回与视频无关的片段；
                  重复取稿会尝试升级，但不保证一次拿到全文，也验不了字幕本身的真假
一次一个 P         合集要逐个取
手账无原地编辑     要改就写修订（设计选择）；修订不可删除，也只可追加
核心的桥默认关     打开才生效；它是只读兜底，不是主线检索路径
面板视觉未验收     逻辑有测试；这台机器上写代码的模型读不了图，
                  布局/字号/对比度没有经过我这一侧的视觉检查
只在私聊生效       群聊与别人的私聊一律不搜、不写、不提示
```

## 九、包内容与获取

```text
GitHub    https://github.com/sishui114727-sys/cognition-study
          Release v0.3.1 附带社区包

社区包    cognition-study-<version>-community.zip     ← 混淆版，发布用这一份
          plugin/（混淆版）+ docs/ + README + INSTALL + LICENSE，拿到就能装

开发者包  cognition-study-<version>.zip               完整包：插件源码 + test/ + scripts/
          cognition-study-<version>-dev.zip           明文 + 文档，不带测试脚本
```

**两份包名字不同，是故意的**：发布出去的一律是 `-community.zip`（混淆）。`-dev` / 完整包是明文，
只在自己改代码、跑测试时用——别把明文包贴到发布页，那等于把源码散出去。

构建      混淆 index.js 与 src/**（panel/ 保持明文）→ 语法检查 →
          对着混淆产物再跑一遍 98 条测试 → 才出包

社区包不含 `test/` 与 `scripts/`。包内 `DIST-INFO.json` 记录版本、构建时间、混淆文件数与社区包 sha256，拿到手可以核对。
