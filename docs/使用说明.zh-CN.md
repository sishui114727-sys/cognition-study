# cognition-study · 学习管线（可选插件）

给 QQ Agent 加一条"看视频 → 留稿子 → 写手账"的链路。**独立插件**，不并入认知核心：核心没装也能跑，装了也不共用数据。

```text
B站视频 → 取稿（字幕 / 只有简介）→ 简报（时间轴要点）→ 手账（每日限量）→ 札记（碎片）→ 检索
```

---

## 一、它到底能做什么

| 能力 | 有 SESSDATA | 没有 SESSDATA |
|---|---|---|
| 读标题、UP、时长、分P、简介 | ✅ | ✅ |
| 读字幕正文（CC / AI 字幕） | ✅ | ❌ |
| 时间轴要点、高频词、数字与术语 | ✅ | 只从简介里抽数字与术语 |
| 写手账、按卷读回、快照校验 | ✅ | ✅ |
| 札记（带标签的碎片） | ✅ | ✅ |
| 关键词检索稿件 / 手账 / 札记 | ✅ | ✅ |

没有字幕时，稿件会被**明确标注 `coverage: metadata-only`**，简报第一行就写「这份稿件只有标题与简介，没有读到正文」。不伪造要点，也不假装读完了。

**字幕路径已实测（2026-10-31，本机）**：

```text
匿名 16 个样本    0 命中。字幕对象被裁到只剩 allow_submit=false、lan 为空——
                 不是"这些视频没字幕"，是登录态才给列表。
带 SESSDATA       同一批样本立刻拿到 ai-zh（AI 字幕）。
                  实测样本：某 TED 合集第 1P，260–416 段 / 2550–5074 字。
```

两个实测的坑，代码里都处理了：

```text
限流   短时间连问十几个视频后，会返回 code 0 但字幕数组为空；过一会儿又有。
       插件会重试一次，并把原因标成 NONE_MAYBE_THROTTLED，不当作"没字幕"。
波动   AI 字幕每次返回的段数/字数可能不同（实测见过 9 / 260 / 416 / 1476 段）。
       1476 段那次折合 1300 字/分钟，正常口播到不了，是异常返回。
       规则：默认保留首份；新内容 ≥1.5 倍且语速 ≤600 字/分钟时覆盖；
       首份本身不可信时，允许换成可信的更短版本。id 不变，手账引用不断。
```

为什么没做 ASR：同一天实测匿名可以直接下载音频流（5.9MB / HTTP 200），但本地转写要几百 MB 模型 + 可执行文件，和"零依赖、随插件加载"冲突。取舍见 `docs/设计说明.md` 第五节。

## 二、装

```text
1. 解压，把整个 cognition-study/ 目录放到：
   <QQ Agent 安装目录>\resources\app\plugins\cognition-study
   （plugin.json 必须在这一层）

2. 把目录名加进 config.trustedPlugins
   这个插件要读写本地文件（node:fs），宿主会拦"高危能力"。
   报错原文会告诉你填什么：
     "触碰了高危能力：host.js（导入了高危 Node 模块）… 请在 config.trustedPlugins 里加入它的目录名"
   往 config.json 的 trustedPlugins 数组里加 "cognition-study"。

3. 完全退出 QQ Agent，重启。

4. 设置 → 插件 → 学习管线：
   启用学习管线 ✅ / 主人 QQ 号 / 每天最多新建手账（默认 2）/ 每天手账字数（默认 6000）
   SESSDATA 可选，填了才有字幕。
   主人发链接时自动提示学习：可选，打开后私聊发 B站 链接她会认出来（默认关）

5. 重启一次，确认工具列表出现 16 个 study_* 工具。
```

默认 `enabled: false`：装上去不会自己跑，必须手动打开。

## 三、十六个工具

**取稿与读稿**

```text
study_fetch          BV 号或链接 → 取稿（先查时长与额度，再打网络）
study_list           最近稿件列表（不返回正文）
study_read           读一篇：简报 + 正文（1500 字/页，可翻页）
```

**手账**

```text
study_journal_write    写一篇（每天 2 篇 / 6000 字上限，超了明说）
study_journal_list     倒序列出，不带正文；可按天或区间筛、可分页
study_journal_get      读一篇：原条目 + 全部修订
study_journal_amend    追加修订，指向原 id；不占额度
study_journal_stats    连续天数、本周、平均字数、覆盖率、失效引用
study_journal_export   导出成一份 Markdown（按天分组、修订跟在后）
study_journal_index    取索引：总篇数、分卷、当前快照
study_journal_volume   按卷读正文，必须带快照；长卷 6000 字/页
study_journal_repair   索引/分卷坏了就重建，账本不动
```

**札记与检索**

```text
study_note_write     记一条碎片（≤600 字，必须带标签或稿件 id）
study_note_list      按标签 / 稿件 id 翻
study_search         在稿件、手账、札记里搜；没命中就返回空数组
```

**状态**

```text
study_status         稿件数、今日取稿、手账额度、校验结果（完整统计用 study_journal_stats）
```

全部 owner-only：只有设置里那个主人 QQ 号能触发。

## 四、一天是怎么用的

```text
1. 主人发来一个视频链接
2. 模型调 study_fetch → 拿到 id 与简报
3. 模型读 study_read → 拿到带时间轴的要点和正文
4. 模型写 study_journal_write → 一篇手账（今天第 1/2 篇）
5. 想记一句就 study_note_write，带 tag
6. 以后要找回：study_search "凭证"
```

打开「主人发链接时自动提示学习」之后，第 1 步可以只是"主人发个链接"：
插件在她私聊的消息尾部加一行提示（BV 号 + 是否已取过稿），她据此调工具。
钩子不下载，所以不会卡住对话；群聊和别人私聊不触发。

手账的额度按**账本**统计，不读缓存：重启宿主、进程崩溃、换机器，额度都不会被重置。同内容重复提交不消耗额度（幂等）。

## 五、手账怎么用

七个动作，覆盖"写、看、改、导、修"：

```text
写     study_journal_write   标题 + 正文（Markdown）。每天 2 篇、6000 字上限
看列表 study_journal_list    倒序、不带正文；可按 day 或 from/to 筛，支持分页
看一篇 study_journal_get     原条目 + 全部修订（按时间正序）
改     study_journal_amend   追加一条修订，指向原手账 id；不占额度
看进度 study_journal_stats   总篇数、连续天数、本周、平均字数、覆盖率、失效引用
导出   study_journal_export  按天分组成一份 Markdown，写到 data/exports/
修索引 study_journal_repair  索引/分卷坏了就重建，账本一条不动
```

### 为什么是"修订"而不是"编辑"

手账是写给自己看的，改主意是常态。但如果直接覆盖，三个月后你就不知道当时为什么那么想了。
所以改一篇 = 追加一条带 `revises` 的新条目：

```text
原条目    永远原样保留在账本里
修订条目  指向原 id，列表和导出默认展示最新一版
```

修订不占当天额度——它不是新的一天里的新想法，是改错字。

### 两道额度闸

```text
篇数   每天 2 篇（dailyJournalLimit，可改）
字数   每天 6000 字（maxJournalCharsPerDay，可改）
```

只有第一篇是 2 篇里的一道，第二道防的是"两篇各八千字"。超了会说清楚超了多少，
读取和检索完全不受影响。

### 读卷为什么老让我先取快照

手账按 24KB / 350 行切卷。读卷必须带 `study_journal_index` 返回的快照：

```text
快照一致   正常返回（长卷自动按 6000 字分页，返回 nextOffset）
快照过期   拒绝读取，提示重新取索引
```

宁可多调一次工具，也不拿旧快照读新卷——那样会读到半新半旧的分卷，比报错更糟。

### 引用失效会如实标出来

手账可以引用稿件 id。如果那篇稿件后来被清理了，手账**照样写成功**，
但条目里会留 `missingRefs`，面板和 `study_journal_stats` 都会显示"有几篇引用的稿件已不存在"。
不静默删引用，也不因为引用失效就拒绝写手账。

### 导出长什么样

```markdown
# 学习手账

- 导出范围：2026-10-01 ~ 2026-10-31
- 条数：12

## 2026-10-31（示例）

### 凭证最小化

- 时间：2026-10-31T21:10:00+08:00
- 覆盖：full · 来源 r:BV1UbyZB9ERb:1:217975bb

正文……

> 修订于 2026-10-31T22:02:00+08:00：

> 改过之后的正文
```

导出只写文件、不覆盖：文件名带时间戳，写进 `data/exports/`。

## 六、数据在哪

```text
data/plugin-data/cognition-study/
  readings/readings.jsonl   稿件元信息（一行一篇）
  readings/raw/*.txt        原始字幕正文（可关）
  readings/brief/*.md       简报 Markdown
  journal/ledger.jsonl      手账账本（唯一真相）
  journal/index.json        索引与快照（派生，可重建）
  journal/volumes/v-*.md    手账分卷（派生，可重建）
  notes/notes.jsonl         札记
  exports/journal-*.md      导出的手账
  exports/journal-*.md      导出的手账（study_journal_export 写的）
```

删掉 `index.json` 和 `volumes/` 不会丢手账：`ledger.jsonl` 是唯一真相，下次读取会自动重建。反过来，账本坏了就是真坏了——那时会明确报错，不会静默跳过。

## 七、和记忆核心的关系

```text
数据     各存各的：data/plugin-data/cognition-study/ 与 cognition-core/
代码     零耦合：核心提到 study 0 次；study 脚本与源码不 import 核心
检索     study_search 只搜稿件/手账/札记；核心 0.24.0 起可用只读桥（默认关）
B站      核心的 bili.video 只给元信息；要正文用 study_fetch
上下文   核心按预算注入记忆；study 只在主人私聊贴链接时加一行（默认关）
```

两边都开不冲突，但要注意三件事：

```text
1. 别用核心的 bili 读正文——它只有标题/UP/时长/简介
2. 两个注入都开时上下文会多两段；嫌贵先关一边，功能不受影响
3. 想让核心也能搜到手账：核心设置 → 读取学习手账（默认关，只读，不写手账）
```

## 八、出问题怎么查

| 现象 | 原因 | 处理 |
|---|---|---|
| 插件列表里有，但工具不出现 | 高危能力被拦 | 把目录名加进 `trustedPlugins` |
| `缺少 skill.json / plugin.json` | 目录多套了一层 | `plugin.json` 必须直接放在插件目录里 |
| 所有工具都回「只对主人开放」 | `ownerId` 没填或填错 | 设置里填主人 QQ 号 |
| `NO_SESSDATA` / coverage 一直是 metadata-only | 没配 SESSDATA | 填 SESSDATA，或在文档里接受"只读简介" |
| 取稿回「超过上限」 | 单P时长超过设置 | 调大「单次取稿时长上限」或换短视频 |
| 取稿回「今天已取稿 N 次」 | 日取稿上限 | 明天再取，或调大上限 |
| 写手账回「已达上限」 | 日手账额度 | 明天再写，读取不受影响 |
| 读卷回「快照已失效」 | 期间有人写了新手账 | 重新 `study_journal_index` 拿新快照 |
| 读卷回「校验未通过」 | 索引/分卷与账本不一致 | 调 `study_journal_index` 会触发重建；仍失败则账本真被改过 |
